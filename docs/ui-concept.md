# Dopa UI — 確定したワイヤーフレーム

ブラウザでの画面構成・文言・操作の検討を基に、メインウィンドウを持たないメニューバー常駐のSwiftUIアプリを `.app` バンドルとして実装した。現行の設計契約は [DESIGN.md](../DESIGN.md)、実画面の確認項目は [実機受入れ](acceptance.md) に記録する。ブラウザデモ自体はデーモン接続や電源操作を行わない。

この文書は操作と概念的な配置の仕様である。SwiftUI実装では標準Liquid Glassコンポーネントを使い、Webの寸法・色・影を模倣しない。タブバーも標準のLiquid Glass表示へ置き換える。

## このアプリタブ

時間設定と2つのスイッチを置き、「開始／停止」で自分のセッションを操作する。

時間と終了時刻、開始／停止・キャンセル・適用をひとつのグループにまとめる。時間管理グループの操作欄はすべて右揃えにし、通常時は開始／停止、実行中に手入力で時間を編集中の場合だけキャンセルと適用を表示する。両者は同時に表示しない。その下に余白を空け、2つのスイッチを別のグループとして配置する。

| 項目 | 動作 |
| --- | --- |
| 時間／残り時間 | HH:MM:SSで編集。初期値1時間 |
| 無制限 | 専用チェックボックスで切り替え。オンの間は期限を設けず、時間・終了時刻の入力を無効にする。実行中の切り替えは適用まで未確定 |
| 時間を追加 | 2つの入力行の下の共通エリアに「＋15分」「＋30分」「＋1時間」のピルボタンを配置。停止中・実行中ともに押した分を累積し、即時反映 |
| 終了日時 | macOS標準NSDatePickerで日付と時刻を秒まで一つのDate値として編集。選択した日時をそのまま使う |
| ディスプレイをオフにしない | 初期オフ。実行中も変更できる |
| ふたを閉じたら停止 | 初期オフ。UI自身がローカルに蓋を監視し、閉蓋時に自分の `session.release` を送る。実行中も変更できる |

時間と終了日時は同じ期限の2つの表現として連動する。継続時間は時・分・秒を個別に選択する右揃えの数値入力、終了日時はmacOS標準NSDatePickerで日付と時刻を秒までまとめて編集する。日時欄の表示は数値ロケールでyyyy-MM-dd HH:mm:ss相当に揃え、各日時要素を選択して編集する標準操作を保持する。入力欄の枠線・背景・左側のtimer/calendarアイコンは共通の外観にまとめ、継続時間にはAppKitの数値TextFieldを3個、終了日時にはNSDatePickerを使う。枠と背景にはシステムの意味的な色を使う。2つの入力行は同じ高さで揃え、ラベルと入力欄を各行の中央に配置する。停止中のラベルは「継続時間」、実行中の確定値は「残り時間」。タイマーアイコンは通常の文字と同じprimary色で入力欄内に置く。終了欄に独立した日付の補助表示や「今日／明日」は付けない。無制限では両入力を無効にし、ラベル・入力欄の位置を変えない。その下の共通エリアに左から「無制限」と時間加算ピルを置く。通常幅では横一列、狭い幅では折り返す。

開始／停止・キャンセル／適用の操作欄は1行分の高さにまとめる。停止中の手入力は有効な値を即時反映し、開始ボタンを表示したままにする。不正な値は保存せず、修正されるまで開始を無効にする。実行中の手入力のときだけ停止を隠し、「キャンセル」と、有効な変更がある場合の「適用」を右端に表示する。キャンセル・適用後は停止へ戻すが、入力欄へフォーカスを戻さない。入力行の高さを保持し、無制限や編集状態の切り替えでパネルを伸縮させない。

入力エラーは操作欄から外し、該当する時間／終了時刻の入力欄に紐づくポップオーバーで表示する。数値編集中は表示を抑え、途中の日付入力を中断しない。入力フォーカスを維持し、一度に表示するのは1つだけにする。修正すると自動で閉じ、閉じるボタン・Escape・外側のクリックでも閉じられる。エラーが残っていれば、入力を変更するか対象欄に戻ると再表示できる。パネルのサイズは変えない。

ネイティブ化する場合は、SwiftUI標準の `popover(isPresented:attachmentAnchor:arrowEdge:content:)` を各入力欄に紐づける設計にできる。エラー判定と表示文言はアプリ側で用意する。ブラウザデモはこの表示・操作の参照に使い、SwiftUI実装では標準のプレゼンテーションを採用する。

参照：[SwiftUI — popover](https://developer.apple.com/documentation/swiftui/view/popover%28ispresented%3Aattachmentanchor%3Aarrowedge%3Acontent%3A%29)、[HIG — Writing](https://developer.apple.com/design/human-interface-guidelines/writing)。

- **時間を手入力**：停止中は設定を即時反映し、開始した時点からその長さを数える。実行中は適用した時点から数え直す。
- **終了日時を編集**：停止中は有効値を即時反映、実行中は適用で確定する。過去の日時を翌日へ読み替えず、エラーとして修正を促す。24時間以内の選択日時をDateとして保持する。
- **ピルボタンで追加**：停止中・実行中ともに即時反映し、確認操作は挟まない。有効な手入力の編集中なら表示中の値に加算してまとめて反映し、なければ現在の設定に加算する。実行中や終了時刻の設定では元の終了予定に指定分を加え、停止中の時間設定は相対時間として加算する。無制限ではすべての加算ボタンを無効にする。入力が不正・期限切れの場合や、加算後に24時間を超えるボタンは無効にする。
- **無制限を選択**：停止中は即時反映。実行中はオン・オフとも未適用の変更とし、キャンセル／適用を表示する。オンの入力表示では両欄を空欄にして無効にするが、適用前は元の期限とスリープ防止を維持する。オフの入力表示では記憶した長さを復元し、適用した時点から数え直す。キャンセルや元のモードへの切り戻しでは適用済み状態を維持する。適用前に元の期限へ達した場合は終了し、未適用の変更を破棄する。文字列入力で無制限へ切り替える方法は設けない。
- 実行中の手入力は、適用前に終了予定を変更しない。キャンセルすると元の予定に戻る。
- 実行中の手入力中でも元の期限に達したら終了し、未適用の編集を破棄する。
- 実行中の手入力をキャンセル・適用するかピルで反映すると、停止ボタンへ戻る。
- 終了時刻で適用した設定は、開始を遅らせても時刻を動かさない。すでに過ぎていれば再設定を案内する。
- 時間は1秒〜24時間。不正な値と、編集中に過ぎた終了時刻は適用しない。
- 2つのスイッチは時間の適用とは独立して変更する。

停止中の説明文は置かない。通常の起動やパネルの再表示だけでセッションを始めない。パネルを開いた直後は入力欄を自動選択しない。メニューバー項目は固定幅とし、アイコンを拡大縮小せず標準の自然サイズで表示する。パネルはメニューバー項目のwindow content領域へ位置を合わせ、シンボルの形状変更によるボタンの高さ変化へ追従しない。

用語はmacOSの慣例に合わせ、「キャンセル」は未適用の変更を破棄し、「適用」は編集画面を閉じずに変更を反映する意味で使う。「適用」はこの操作に合わせたラベルであり、Appleがあらゆる画面に指定する固定語ではない。

参照：[HIG — アラート](https://developer.apple.com/jp/design/human-interface-guidelines/alerts)、[Macのスリープ／スリープ解除を設定する](https://support.apple.com/ja-jp/guide/mac-help/mchle41a6ccd/mac)。

## 全体管理タブ

上部タブで切り替え、アプリとCLIの一覧・個別停止・すべて停止を表示する。通常タブの停止はアプリ自身のスリープ防止だけに作用する。各行はPIDとdaemonが管理する「ディスプレイオフ防止」のオン／オフを表示し、設定は閲覧のみとする。閉蓋監視は各クライアントのローカル設定であり、一覧のdaemon状態には含めない。

パネルの標準幅は380ptとし、文字サイズと220ptの入力幅を維持する。両タブは「このアプリ」の自然サイズを共有し、全体管理をその領域へ重ねて表示する。高さを状態変数へ書き戻す測定ループは設けない。パネルの寸法は開く前に決定し、表示中の状態変化でpopoverを自動リサイズしない。切り替えや一覧件数の変化でパネルの位置・サイズを変えない。全体管理は一覧部分だけを縦スクロール領域にし、「すべて停止」は下部に固定する。非選択のタブの操作要素はフォーカスや読み上げの対象から外す。

ネイティブ実装の切り替えは、追加の参考画像に合わせてカプセル形の下地と選択側のLiquid Glassで構成する。標準ButtonとglassEffectを使い、選択状態を読み上げへ伝える。選択部分の移動には標準アニメーションを使い、Reduce Motion時は省く。時間設定と動作設定の2グループをさらに囲む外枠は設けず、内容の実測高を共有して下部に余分な空間を足さない。

- このアプリの個別停止は、どちらのタブからでも確認を挟まず実行する。
- 同じユーザーのCLIなどは管理者認証なしで停止できる。別ユーザーの対象には管理者認証を使う。CLIの個別停止と全体停止には確認ダイアログを挟み、停止対象とその結果を伝える。CLIだけを停止してこのアプリが残る場合は、スリープ防止が継続することを明示する。
- ボタンは「スリープ防止を停止」「すべて停止」とし、タイトルと対象一覧で操作の範囲を明示する。「終了」はアプリ自体の終了と混同しやすいため、継続中の機能を止める操作には「停止」を使う。
- キャンセル時は操作元へ戻り、停止して行が消えた場合は残った操作または全体管理タブへキーボードフォーカスを移す。

デモではCLIを1件起動済みとして表示する。実際のプロセス一覧ではない。ヘッダはタブによらず全体の状態を表示し、全体の件数はタブにも表示する。

| ヘッダの表示 | 条件 |
| --- | --- |
| スリープ防止中 | このアプリが実行中。ほかのアプリやCLIも動いている場合を含む |
| 他のアプリやCLIが動作中 | このアプリは停止中だが、Dopaを使うアプリやCLIが実行中 |
| オフ | すべてのアプリとCLIが停止中と確認できた場合 |

状態は色だけでなく文言で区別し、タブを切り替えても表示を変えない。開始・停止・自動終了で状態が変わったときだけ読み上げにも通知する。

接続案内・操作結果のメッセージ・処理中表示は既存のヘッダー内に収める。案内がある場合は状態表示を押して詳細のポップオーバーを開く。下部にメッセージ行を追加せず、接続中・接続済み・切断・処理中・メッセージの有無や長さで本体の高さを変えない。

`cli=12` のようなURL指定で一覧のスクロールを試せる。CLI件数は既定1件、0〜50件で、個別停止できる模擬PIDを表示する。個別停止後は近くの項目へフォーカスを移し、一覧のスクロール位置を保つ。

## 管理者権限を求めるタイミング

全体管理に管理者権限が必要な場合は、その機能を初めて利用する時点でmacOS標準の認証を求められる。起動時には要求しない。

- タブの表示自体に権限が必要なら、初回のタブ選択時に要求する。キャンセル時は元のタブに留まり、次にユーザーが選択した時だけ再試行する。
- 一覧の閲覧に権限が不要なら、タブはそのまま開く。権限が必要な個別停止・全体停止を実行する直前に要求する。キャンセル時は一覧と実行状態を維持する。
- 一度の成功を永続的な許可とは扱わず、実行時に有効な権限を確認する。必要な場合だけ再認証する。
- バックグラウンドサービスの登録・起動承認と、個々の管理操作の認証は別に扱う。認証情報はmacOS標準の認証UIで扱う。

ネイティブ実装では一覧の閲覧と同UIDの停止に非特権APIを使い、別UIDの管理停止で必要な場合だけ直前に管理権限を取得する。具体的なAPIと認可の契約は [DESIGN.md](../DESIGN.md) に記録している。このブラウザデモには実際の権限取得や認証画面の模倣を追加しない。

参照：[Apple — Authorization Services Tasks](https://developer.apple.com/library/archive/documentation/Security/Conceptual/authorization_concepts/03authtasks/authtasks.html)、[SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice)。

## Liquid Glassに向けたデザイン方針

実行中の手入力の適用は入力欄の下で行い、停止中の編集・ピル操作・無制限の切り替えは即時反映する。入力エラーは該当欄に紐づくポップオーバーで示して操作の文脈を保つ。確認ダイアログは、ほかのアプリやCLIにも影響する停止や一括停止に絞る。ガラス素材はナビゲーションや操作の階層を中心に使い、設定行へ重ねない。ブラウザデモでは素材や変形アニメーションの再現は行わない。

ネイティブ実装ではmacOS標準の確認表示とアクセシビリティ設定に従い、操作元とのつながりを保つ。計画コミット `a8b51a9` の後にSwiftUI実装を開始した。

参照：[Apple — Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/)、[HIG — Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts)。

## 試す

```sh
mise exec -- python3 -m http.server 4317 --bind 127.0.0.1 --directory prototypes/ui
```

- 待機中：http://127.0.0.1:4317/
- 実行中：http://127.0.0.1:4317/?state=running
- 全体管理：http://127.0.0.1:4317/?state=running&tab=global
- スクロール確認：http://127.0.0.1:4317/?state=running&tab=global&cli=12

`state=running` は残り47分23秒の模擬セッションから始まる、表示確認専用の指定。

ブラウザの時刻・適用処理の検証：

```sh
mise exec -- node --test prototypes/ui/schedule.test.mjs
```

## ネイティブ実装との対応

以下はSwiftUI実装で満たす通信・状態の条件である。具体的なAPIは [DESIGN.md](../DESIGN.md)、検証手順は [README](../README.md) と [実機受入れ](acceptance.md) を参照する。

- 自分の開始は `session.acquire`、終了は `session.release`。UIの閉蓋トグルが有効な間はUI自身が蓋を監視し、閉蓋時に自分の `session.release` を送る。
- デーモンの `session.update` は `keepDisplayOn` だけを完全置換する。閉蓋トグルは daemon options や snapshot に含めない。
- 応答と最新の確認状態を取得してから適用済みとして扱う。閉蓋監視の読み取り失敗や release の確認失敗は UI 側のエラーとして表示し、daemon の状態理由へ変換しない。
- 時間の適用はUIで期限を管理し、期限到達で終了要求を送る。デーモンにタイマーAPIを追加する必要はない。
- 全体管理は同UIDに `session.stopSessions`、管理者権限が必要な対象に `admin.stopSessions` を使い、同名capabilityで交渉する。確認済みIDだけを停止し、所有者へ `user_stopped` を通知する。同UID判定はデーモンがカーネル取得UIDで行い、通常のrelease/updateの接続所有権は維持する。
- `admin.prepareShutdown` はサービスを終了準備状態にする管理操作なので、全体管理タブの終了操作には流用しない。全体終了後もサービスは次の開始を受け付ける。
- 終了や復元の失敗を成功と表示しない。実機接続時は、CLIが残っている場合の全体状態も取得する。

ブラウザデモは表示・操作の検討用で、CLI・デーモン・公開APIへ接続しない。ネイティブ実装の通信・認可契約と実画面検証の範囲は [DESIGN.md](../DESIGN.md) と [実機受入れ](acceptance.md) を参照する。

## ネイティブ操作ボタン

通常の操作ボタンは標準glass、開始と適用はglassProminentにシステムのaccentColorをtintとして明示し、主操作を区別する。時間追加3つは無着色の標準glassボタン、capsule形状、smallサイズで、通常ボタンと区別しつつ控えめにする。独自の背景色や枠線は追加しない。画像指定のタブ切り替えはLiquid Glassを維持する。

### フォーカスと固定基準

最後に変更を始めた時間／日時を計算の基準にする。クリック・フォーカス・Tab／左右キーでの選択移動だけでは基準を変えない。数字入力・削除・上下キーでの増減を始める瞬間に対象の値を固定する。固定している入力欄のすぐ左にピンアイコンだけを表示し、無制限時は表示しない。実行中の基準変更は編集として保持し、適用までは稼働中の期限を変更しない。開始・適用後は確定した終了日時へ固定表示を戻す。停止後は最後に適用した設定へ戻し、継続時間で設定した場合はその長さ、終了日時で設定した場合はその日時を固定する。残り時間への変換は行わない。固定状態は独立したフラグを持たず、未適用の入力種類、実行状態、保存済み設定から導出する。不正な入力は選択移動だけでは破棄しない。

アプリの終了はメニューバーアイコンの右クリックメニューへ置く。通常クリックは操作パネルを開閉し、パネル内に終了ボタンは置かない。

全体管理タブのタイトルは件数を含めず「全体管理」とする。件数は一覧下部の左に「N件」と表示し、同じ行の右に「すべて停止」を置く。

### 時・分・秒の操作の統一

両入力欄は共通のAppKitコントロールで「欄の選択」と「数値編集」を分離する。Tab／Shift-Tabは欄全体を巡回し、数字は選択しない。Enterで必ず左端の数値から編集を開始する。マウスではクリックした数値を直接編集する。編集中はTab／Shift-Tabで右／左の要素へ移動し、最後／最初の要素からは次／前のコンポーネントへ抜ける。左右キーでも要素を移動でき、数字入力と上下キーで値を変更する。編集中のEnter／Escapeは欄全体へ戻る。フォーカス枠は選択中・編集中ともアイコンを含む欄全体に付ける。Enterだけでは固定基準や実行中の適用状態を変えない。日付に変換せず継続時間として扱い、上限24:00:00を翌日00:00:00へ折り返さない。

編集中の継続時間の要素は、終了日時に合わせてシステムの選択アクセント色の角丸背景と白い数字で表示する。1桁目の入力中も要素全体を強調し、細い挿入カーソルは表示しない。各要素専用のフィールドエディタで描画するため、他のテキスト欄の選択表示には影響しない。

採用前にApple NSDatePicker、mac-gallagher/DurationPicker、DejalIntervalPickerを調査した。NSDatePickerは日付と時刻（またはその範囲）向けで継続時間の入力モードを持たず、DurationPickerはUIKit/iOS専用、DejalIntervalPickerは数値＋単位方式のため、HH:MM:SSを編集する今回の要件にはそのまま適用できない。AppKit標準のテキスト編集・選択を使用した3要素入力を採用する。

参考: [NSDatePicker](https://developer.apple.com/documentation/appkit/nsdatepicker)、[DurationPicker](https://github.com/mac-gallagher/DurationPicker)、[DejalIntervalPicker](https://github.com/Dejal/DejalIntervalPicker)。

全体のディスプレイオフ防止が確認されている間だけ、ヘッダーに小さなdisplayアイコンと「ディスプレイオフ防止」を表示する。両タブ共通で、自分のスイッチがオフでも他のアプリやCLIにより有効なら表示する。長い説明は置かず、閉蓋監視の設定は「このアプリ」タブのローカル設定として示す。未接続・未確認状態では有効表示を出さない。
