# dopa UI — 確定したワイヤーフレーム

ブラウザでの画面構成・文言・操作の検討は完了した。2026-09-12の依頼で、メインウィンドウを持たないメニューバー常駐のSwiftUIアプリを `.app` バンドルとして実装する段階へ進む。再開用の計画は `PLANS.md` に記録する。ブラウザデモ自体はデーモン接続や電源操作を行わない。

この文書は操作と概念的な配置の仕様である。SwiftUI実装では標準Liquid Glassコンポーネントを使い、Webの寸法・色・影を模倣しない。タブバーも標準のLiquid Glass表示へ置き換える。

## このアプリタブ

時間設定と2つのスイッチを置き、「開始／停止」で自分のセッションを操作する。

時間と終了時刻、開始／停止・キャンセル・適用をひとつのグループにまとめる。時間管理グループの操作欄はすべて右揃えにし、通常時は開始／停止、実行中に手入力で時間を編集中の場合だけキャンセルと適用を表示する。両者は同時に表示しない。その下に余白を空け、2つのスイッチを別のグループとして配置する。

| 項目 | 動作 |
| --- | --- |
| 時間／残り時間 | HH:MM:SSで編集。初期値1時間 |
| 無制限 | 専用チェックボックスで切り替え。オンの間は期限を設けず、時間・終了時刻の入力を無効にする |
| 時間を追加 | 2つの入力行の下の共通エリアに「＋15分」「＋30分」「＋1時間」のピルボタンを配置。停止中・実行中ともに押した分を累積し、即時反映 |
| 終了時刻 | 時間の下に表示し、時刻からも編集できる。今日／明日を明示 |
| ディスプレイをスリープさせない | 初期オフ。実行中も変更できる |
| ディスプレイを閉じたら停止 | 初期オフ。実行中も変更できる |

時間と終了時刻は同じ期限の2つの表現として連動し、値はどちらも左揃えにする。2つの入力行は同じ高さで揃え、ラベルと入力欄を各行の中央に配置する。「今日／明日」は「終了時刻」の右横に小さく添え、両行とも1行の配置にする。無制限で日付が消えてもラベル・入力欄の位置を変えない。その下の共通エリアに左から「無制限」と時間加算ピルを置く。通常幅では横一列、狭い幅では折り返す。

開始／停止・キャンセル／適用の操作欄は1行分の高さにまとめる。停止中の手入力は有効な値を即時反映し、開始ボタンを表示したままにする。不正な値は保存せず、修正されるまで開始を無効にする。実行中の手入力だけ停止を隠し、「キャンセル」と、有効な変更がある場合の「適用」を右端に表示する。キャンセル・適用後は停止へ戻し、キーボードフォーカスも移す。入力行の高さを保持し、無制限や編集状態の切り替えでパネルを伸縮させない。

入力エラーは操作欄から外し、該当する時間／終了時刻の入力欄に紐づく非モーダルのポップオーバーで表示する。入力フォーカスを維持し、一度に表示するのは1つだけにする。修正すると自動で閉じ、閉じるボタン・Escape・外側のクリックでも閉じられる。エラーが残っていれば、入力を変更するか対象欄に戻ると再表示できる。パネルのサイズは変えない。

ネイティブ化する場合は、SwiftUI標準の `popover(isPresented:attachmentAnchor:arrowEdge:content:)` を各入力欄に紐づける設計にできる。エラー判定と表示文言はアプリ側で用意する。ブラウザデモはこの表示・操作の参照に使い、SwiftUI実装では標準のプレゼンテーションを採用する。

参照：[SwiftUI — popover](https://developer.apple.com/documentation/swiftui/view/popover%28ispresented%3Aattachmentanchor%3Aarrowedge%3Acontent%3A%29)、[HIG — Writing](https://developer.apple.com/design/human-interface-guidelines/writing)。

- **時間を手入力**：停止中は設定を即時反映し、開始した時点からその長さを数える。実行中は適用した時点から数え直す。
- **終了時刻を手入力**：停止中は即時反映、実行中は適用で確定する。入力時にすでに過ぎている時刻は翌日として表示し、指定した終了時刻を保持する。
- **ピルボタンで追加**：停止中・実行中ともに即時反映し、確認操作は挟まない。有効な手入力の編集中なら表示中の値に加算してまとめて反映し、なければ現在の設定に加算する。実行中や終了時刻の設定では元の終了予定に指定分を加え、停止中の時間設定は相対時間として加算する。無制限からは0分を起点に有限の時間設定へ切り替え、無制限のチェックも外す。入力が不正・期限切れの場合や、加算後に24時間を超えるボタンは無効にする。
- **無制限を選択**：停止中・実行中ともに即時反映し、未確定の手入力は解消する。オンでは時間欄を空欄にして無効にし、実行中のスリープ防止はそのまま継続する。オフではオン直前に表示していた時間の長さへ戻す。実行中なら切り替え時点の残り時間を記憶し、オフにした時点から数え直す。文字列を入力して無制限へ切り替える方法は設けない。
- 実行中の手入力は、適用前に終了予定を変更しない。キャンセルすると元の予定に戻る。
- 実行中の手入力中でも元の期限に達したら終了し、未適用の編集を破棄する。
- 実行中の手入力をキャンセル・適用するかピルで反映すると、停止ボタンへ戻る。
- 終了時刻で適用した設定は、開始を遅らせても時刻を動かさない。すでに過ぎていれば再設定を案内する。
- 時間は1秒〜24時間。不正な値と、編集中に過ぎた終了時刻は適用しない。
- 2つのスイッチは時間の適用とは独立して変更する。

停止中の説明文は置かない。通常の起動やパネルの再表示だけでセッションを始めない。

用語はmacOSの慣例に合わせ、「キャンセル」は未適用の変更を破棄し、「適用」は編集画面を閉じずに変更を反映する意味で使う。「適用」はこの操作に合わせたラベルであり、Appleがあらゆる画面に指定する固定語ではない。

参照：[HIG — アラート](https://developer.apple.com/jp/design/human-interface-guidelines/alerts)、[Macのスリープ／スリープ解除を設定する](https://support.apple.com/ja-jp/guide/mac-help/mchle41a6ccd/mac)。

## 全体管理タブ

上部タブで切り替え、アプリとCLIの使用元一覧・個別停止・すべて停止を表示する。通常タブの停止はアプリ自身のスリープ防止だけに作用する。

両タブは「このアプリ」の内容に必要な同じ高さを共有し、切り替えや一覧件数の変化でパネルの位置・サイズを変えない。全体管理は一覧部分だけを縦スクロール領域にし、「すべて停止」は下部に固定する。非選択のタブの操作要素はフォーカスや読み上げの対象から外す。

- このアプリの個別停止は、どちらのタブからでも確認を挟まず実行する。
- CLIの個別停止と全体停止には確認を置き、停止対象とその結果を伝える。CLIだけを停止してこのアプリが残る場合は、スリープ防止が継続することを明示する。
- ボタンは「スリープ防止を停止」「すべて停止」とし、タイトルと対象一覧で操作の範囲を明示する。「終了」はアプリ自体の終了と混同しやすいため、継続中の機能を止める操作には「停止」を使う。
- キャンセル時は操作元へ戻り、停止して行が消えた場合は残った操作または全体管理タブへキーボードフォーカスを移す。

デモではCLIを1件起動済みとして表示する。実際のプロセス一覧ではない。ヘッダはタブによらず全体の状態を表示し、全体の件数はタブにも表示する。

| ヘッダの表示 | 条件 |
| --- | --- |
| スリープ防止中 | このアプリが実行中。他の使用元も動いている場合を含む |
| 他プロセスで動作中 | このアプリは停止中だが、CLIなど他の使用元が実行中 |
| オフ | 全使用元が停止中と確認できた場合 |

状態は色だけでなく文言で区別し、タブを切り替えても表示を変えない。開始・停止・自動終了で状態が変わったときだけ読み上げにも通知する。

`cli=12` のようなURL指定で一覧のスクロールを試せる。CLI件数は既定1件、0〜50件で、個別停止できる模擬PIDを表示する。個別停止後は近くの項目へフォーカスを移し、一覧のスクロール位置を保つ。

## 管理者権限を求めるタイミング

全体管理に管理者権限が必要な場合は、その機能を初めて利用する時点でmacOS標準の認証を求められる。起動時には要求しない。

- タブの表示自体に権限が必要なら、初回のタブ選択時に要求する。キャンセル時は元のタブに留まり、次にユーザーが選択した時だけ再試行する。
- 一覧の閲覧に権限が不要なら、タブはそのまま開く。権限が必要な個別停止・全体停止を実行する直前に要求する。キャンセル時は一覧と実行状態を維持する。
- 一度の成功を永続的な許可とは扱わず、実行時に有効な権限を確認する。必要な場合だけ再認証する。
- バックグラウンドサービスの登録・起動承認と、個々の管理操作の認証は別に扱う。認証情報はmacOS標準の認証UIで扱う。

ネイティブ実装では一覧の閲覧に既存の非特権APIを使い、他接続の停止直前に管理権限を取得する。具体的なAPI拡張と認可検証は `PLANS.md` に記録している。このブラウザデモには実際の権限取得や認証画面の模倣を追加しない。

参照：[Apple — Authorization Services Tasks](https://developer.apple.com/library/archive/documentation/Security/Conceptual/authorization_concepts/03authtasks/authtasks.html)、[SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice)。

## Liquid Glassに向けたデザイン方針

実行中の手入力の適用は入力欄の下で行い、停止中の編集・ピル操作・無制限の切り替えは即時反映する。入力エラーは該当欄に紐づくポップオーバーで示して操作の文脈を保つ。確認ダイアログは、別の操作元にも影響する停止や一括停止に絞る。ガラス素材はナビゲーションや操作の階層を中心に使い、設定行へ重ねない。ブラウザデモでは素材や変形アニメーションの再現は行わない。

将来ネイティブ化する場合は、macOS標準の確認表示とアクセシビリティ設定に従い、操作元とのつながりを保つ。実装は `PLANS.md` のコミット後に開始する。

参照：[Apple — Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/)、[HIG — Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts)。

## 試す

```sh
mise exec -- python3 -m http.server 4317 --bind 127.0.0.1 --directory prototypes/ui
```

- 待機中：http://127.0.0.1:4317/
- 実行中：http://127.0.0.1:4317/?state=running
- 全体管理：http://127.0.0.1:4317/?state=running&tab=global
- スクロール確認：http://127.0.0.1:4317/?state=running&tab=global&cli=12

`state=running` は残り47分23秒の模擬セッションから始まる、表示確認専用の指定。

ブラウザの時刻・適用処理の検証：

```sh
mise exec -- node --test prototypes/ui/schedule.test.mjs
```

## 将来の実装に向けた確認事項

以下はSwiftUI実装で満たす通信・状態の条件である。具体的な追加APIと検証は `PLANS.md` に従う。

- 自分の開始は `session.acquire`、終了は `session.release`。
- デーモンはすでに `session.update` に対応している。実行中の変更は、所有する `sessionId` と `keepDisplayOn` / `stopOnLidClose` の完全な組を送信する。
- 応答と最新の確認状態を取得してから適用済みとして扱う。ふたが閉じている状態で `stopOnLidClose` を有効にすると `lid_closed` で拒否されるので、直前の確認済み設定を表示して理由を伝える。
- 時間の適用はUIで期限を管理し、期限到達で終了要求を送る。デーモンにタイマーAPIを追加する必要はない。
- **全体管理はAPI拡張が必要**。現行APIは他接続の更新・終了を認めない。管理能力の通知、管理を許可する認証、他セッションの個別／一括終了と所有者への終了通知を定義する。
- `admin.prepareShutdown` はサービスを終了準備状態にする管理操作なので、全体管理タブの終了操作には流用しない。全体終了後もサービスは次の開始を受け付ける。
- 終了や復元の失敗を成功と表示しない。実機接続時は、CLIが残っている場合の全体状態も取得する。

ブラウザデモの検討ではCLI・デーモン・公開APIを変更していない。ネイティブ実装では全体管理に必要な変更を計画に沿って追加する。
